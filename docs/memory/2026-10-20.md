### 设计取舍

| 问题 | 选择 | 理由 |
|---|---|---|
| 818 卡片身份 | **3 字母键**（JAD） | 数据里 818 = J 开头角块键 378 + G 开头棱块键 440；J/G 是默认方案的缓冲位，这组键恰好每个 case 一条。用「末尾两字母配对」会错：同配对在角块有 1–6 个、棱块 1–10 个互不重叠的 case |
| 算法数据 | 新增 `alg818.txt`（1.68MB，50804 条） | 原 5 个 JSON 合计 30MB+，原生页只读 818 条即可；生成脚本带自检 |
| 推荐算法 | `*AlgToNightmare` 的值 | 官方已选最优；下标 0 占多数，列表不按步数排序 |
| 最优自选 | SP `alg818_best_<KEY>`，★ 再点取消 | 每 case 独立，不依赖算法列表顺序 |
| 调度 | 复用 SRS（box 0–6 / 10min / 1–3–7–15–30–60 天） | 用户明确说「参考联想词的模式」 |
| 混合 | 角 + 棱合并后 shuffle | 与「角块 / 棱块」两个 tab 并列，队列独立计算 |
| 正面内容 | 只露联想词 + 类型徽章 | 先看公式等于泄题（与 SRS 页同一原则） |

### 坑

1. **「再学」按钮在当日额度用尽后消失**：`emptyMore = min(NEW_BATCH, min(allowance, fresh))` → allowance=0 时得 0；改成 `min(NEW_BATCH, fresh)`（手动加餐不受额度限制）。
2. **取消星标写空串**：`sp.put(key, "")` 会留 818 个空键 → 改用 `sp.remove(key)`（真实 `SPUtils` 有 `remove(String)`，stub 也有）。
3. **自检误报 300 条**：818 配对唯一性必须**按类型**校验，角/棱共用 300 个字母配对。
4. **adb shell sed 改 SP 带引号会静默不匹配** → 用 base64：`$b64=[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($script)); adb shell "echo $b64 | base64 -d | sh"`（改前先 force-stop）。
5. `uiautomator dump` 全量 XML 极大 → 用 `[regex]::Matches($x, 'text="([^"]+)"[^>]*?bounds="(\[\d+,\d+\]\[\d+,\d+\])"')` 只取文本+坐标。
