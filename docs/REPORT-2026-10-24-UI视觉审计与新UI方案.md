# 三盲助手 UI 视觉审计与新 UI 方案

- 日期：2026-10-24
- 基准版本：`dist/三盲助手-6.3.2-公式配色版.apk`
- 评审基准截图：`dist/verify-shots/`（24 张，1080×2220 @3x，10-22 生成）
- 约束：**底层逻辑、数据流、状态机全部不变**，只改表现层（颜色 / 字体 / 间距 / 圆角 / 层级 / 组件样式）

> **勘误（2026-10-24 晚补注）**：本文写于深入资源树之前，有两处判断被后续实施证伪，以 `docs/REPORT-2026-10-24-UI令牌收敛版.md` 为准：
> 1. 第 226 行「新增 `dimens.xml` / `colors.xml`」——这两个文件**本来就有**（`src/res/values/` 下 colors.xml 16KB、dimens.xml 15KB、styles.xml 175KB、theme_schemes.xml 79KB），颜色属性也不是 168 个而是 **172 个 `app_*` attr（其中 147 个 `app_lit_*`）**，8 套配色各 172 item。真正的问题不是「没有令牌」，而是令牌是**机械别名**（如 `app_lit_bg_006366f1` 在 teal 方案下取的是 `#0067ede2`），语义错位。
> 2. 「深色顶栏品牌断裂」不成立——`app_bar_bg` 本来就每套 scheme 各配值。

## 0. 测量方法

所有颜色与尺寸都是从截图像素直接采样得出（Pillow 逐像素扫描），不是目测估计。
1080×2220 为 3x 密度屏，因此 **px ÷ 3 = dp**。

## 1. 视觉一致性审计（实测）

### 1.1 颜色漂移：同一个语义有多个色值

| 语义 | 截图里实际出现的值 | 数量 |
| --- | --- | --- |
| 品牌主色 | `#4F46E5`（顶栏/主按钮）、`#6366F1`（图表/链接）、`#6660F0`（按钮渐变中段）、`#818CF8`（深色强调） | 4 |
| 页面底色 | `#F8F9FB`（主页）、`#F5F6F8`（趋势）、`#FAFAFA`（记忆/学习） | 3 |
| 卡片/白面 | `#FFFFFF`、`#FDFDFF`、`#FCFDFF`、`#F7F8FF`、`#F6F8FB`、`#F8FBFF` | 6 |
| 描边/分割线 | `#E3E6EB`、`#E1E1E1`、`#DDDDDD`、`#EEF4FF` | 4 |
| 正文/次要文字 | `#212121`、`#6B7280`、`#999999` | 3 |
| 危险红 | `#FF1C31`、`#FF1A1D`、`#FF251F`、`#FF2125`、`#FF2024`、`#FF1F2C`、`#FF1D18`、`#FF191C`、`#FF1823`、`#FF2228` | 10 |

> 10 种「看起来一样」的红色，说明颜色是逐处手调出来的，没有令牌。这是当前视觉不一致的根因，不是表象。

### 1.2 深浅色主题的品牌表达断裂

| | 顶栏 | 页面底 | 卡片 |
| --- | --- | --- | --- |
| 浅色 | `#4F46E5` 饱和靛蓝 | `#FAFAFA` | `#FFFFFF` |
| 深色 | `#1B1E33` 近黑藏蓝 | `#14161B` | `#1C1F26` |

浅色模式顶栏是最强的品牌锚点，深色模式把它变成了中性深色 —— 而正文里的强调色仍是靛蓝系。结果是**同一份设计在明暗两态下像两个 App**。

### 1.3 三种控件语言并存

1. **胶囊 chip**：训练组数（2-4组/3组/4组/5组/随机）、模式选择（记角/记棱/全读）、818 分段（角块/棱块/混合）
2. **描边分段**：设置页下拉（语音播报秒数 ▾）
3. **系统开关**：计时设置页 7 个 Switch，**用的是系统绿 `#4CAF50` 系，与品牌靛蓝完全无关**

同一个「在 N 个里选 1 个」，出现了三种外观。

### 1.4 图标风格混杂

主页 6 个入口图标：六边形线性（青）、实心文件夹（深灰）、放大镜线性（棕）、尖括号（蓝）、圆圈问号（红）、人形线性（蓝）。
**线宽不一、填充/线性混用、6 个不同色相。** 底部导航 5 个图标同样是线性但粗细不等。

### 2.1 空状态层叠 Bug（趋势页）

`shot-04-trend.png`：空状态文案「暂无分段计时记录 / 在「计时设置」里打开分段计时…」**直接压在三张统计卡和筛选胶囊上**，同时一张破图（图片占位图标）错位叠在「平均复原」卡内。图例「记忆/复原」也浮在文字层上。

这不是审美问题，是布局层叠失效 —— 空状态容器没有正确约束，z 序错乱。

## 3. 信息层级问题

### 3.1 主页（其他 tab）

6 个入口（用户设置 / 资源管理 / 公式查询 / 编码复习 / 用户指南 / 关于作者）**字号、颜色、行高完全一致**，没有主次，也没有分组。
下方 680px（226dp）是纯空白，没有任何内容或收尾信息。

**问题**：进入 App 后第一屏没有任何「该干什么」的引导；六项里高频的「资源管理 / 编码复习」和低频的「关于作者」权重相同。

### 3.2 记忆页（主任务页）

三张卡片（模式选择 / 角块记忆 / 记忆阶段）视觉权重几乎相同，但**真正的任务是第三张卡**。
同时第三张卡里，编码 `7.247` 用的是和正文一模一样的字号与颜色（`#212121`，约 17sp），**没有成为视觉焦点**；下面的 `GF SB NO XH` 反而更大。

### 3.3 学习页（联想词学习）

字号只有两极：`AA` 约 72sp，其余全部约 14sp。**中间层缺失** —— 「第 3 / 20 张」「新词 · 还没复习过」这类进度信息被压到最小号。
卡片内容块整体偏下（卡片 y 250–1330，内容 y 520–1105：上留白 270px、下留白 225px），视觉重心下沉。

### 3.4 818 公式熟练度

`角块` 小胶囊 → `阿迪达斯` 约 64sp → `点击卡片显示公式` 约 14sp。**64sp 直接跳到 14sp**，缺 24/32 这一级，导致标题巨大而说明文字几乎读不清。

背面公式列表：步骤数「15步 / 13步」不是固定列宽，随公式长度左右浮动；星标列虽然是固定的，但数字没有右对齐。

### 3.5 计时设置

9 行设置项全部等权，无分组标题。开关行、下拉行、纯文本行混排，行高一致但控件形态差异大。

## 6. 落地顺序（不改逻辑）

1. **建立令牌文件**：新增 `source/res/values/dimens.xml`（间距/圆角/字阶）、`source/res/values/colors.xml`（浅色）、`values-night/colors.xml`（深色），并把现有 `app_xxx` 主题属性收敛到上述令牌（现在有 168 个颜色属性，可映射压缩到约 30 个）
2. **P0 五项**：趋势页空状态、深色顶栏、818 禁用态、设置页文案、Switch 颜色 —— 都是局部改动，风险最低，先做
3. **全局尺寸替换**：边距 16dp、行高 56dp、按钮 48dp、圆角 16dp —— 纯 `dimens` 引用替换，不碰逻辑
4. **组件样式抽离**：把「胶囊」「分段」「主/次/危险按钮」「卡片」「导航项」抽成 `styles.xml` 里的 style，布局文件只引用
5. **图标重绘**：24dp 网格 / 2dp 线宽 / 单色，一次性替换主页 6 项 + 底栏 5 项
6. **P2 精致度**：字阶应用、联想图统一、公式列表对齐

每一步都可单独出包验证，互不阻塞。
