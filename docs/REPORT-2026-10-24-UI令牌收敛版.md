## 二、为什么能"底层逻辑不变"

这套 UI 的颜色本来就是**三层**结构：

1. **`?attr/app_*`（172 个）** —— 布局和 drawable 里 **2612 处**引用，全部跟随 8 套 ThemeOverlay；
2. **`@color/lit_*`（182 个）** —— 字面量，不跟随主题；
3. **drawable 内裸 hex** —— 只剩 1 处（`bottom_nav_tab_ripple.xml`）。

因为第一层已经铺满了，所以这次**一个 attr 名都没改**，只改它们的**取值**：

```
<item name="app_lit_bg_006366f1">#006366f1</item>   ← 名字保持原样（历史包袱）
                                    ↑ 只动这里
```

2612 处引用自动跟着变，**不可能出现"改了颜色忘了改引用"的编译断裂**。同理，尺寸只改 `@dimen` 的**值**，不改 token 名，也不碰布局里的引用。

### 语义角色的来源

角色判定**只看 attr 名字里的基准 hex**（作者当初是照着靛蓝方案写的，名字里的 hex 就是他的意图）：

- 在 indigo 浅色这一套上做一次 **ΔE 吸附**（阈值 9.0），得到一张全局 role map；
- 8 套 overlay 共用这张表，**不读当前值** → 天然幂等，连跑两次结果完全一致；
- 每个角色再派生：`_container` = mix(role, card, 0.12)（浅色填充）、`_soft` = mix(role, card, 0.35)（描边）、`text_body/secondary/tertiary` = mix(text_primary, card, 0.86/0.60/0.38)。

### 描边为什么要单独一档

第一轮收敛把徽章的**底色**和**边框**都归到了 `success_container` —— 边框和底色同色，边框直接消失了。

扫 `src/res/drawable*` 得到证据：98 个 attr 用于形状，其中 **stroke-only 38 个、solid-only 55 个、两者兼用仅 5 个**（且都是 `app_line`/`app_black` 这类语义色，非 `app_lit_*`）。**描边色和填充色在命名上本来就是分离的**，所以可以安全地给描边单独一档 `*_soft`，每套 overlay 多 18 处改动。

## 三、P0 修复

### 1. 联想词徽章对比度 2.08:1 → 4.73:1

徽章文字色走 `res/color/remember_assoc_badge_on_text.xml` → `@color/green_text`，**全工程只有这 1 处引用**，所以改动是外科手术式的：

| 阶段 | 取值 | 对比度 | 判定 |
| --- | --- | --- | --- |
| 原始 | #00cc00 on #f0fdf4 | 2.08:1 | ✗ 远低于 AA |
| 收敛后（未修文字色） | #059669 on #e1f2ed | 3.25:1 | ✗ 仍不达标 |
| 最终 | **#047857** on #e1f2ed | **4.73:1** | ✓ AA 通过（白底 5.48:1） |

这条修复已固化进 `opt20_palette_gen.py` 的 `ensure_badge_text()`，避免重建时被重新解包出来的 `colors.xml` 冲掉。

### 2. 深色顶栏"两种品牌表达"——复查后判定为**不是缺陷**

审计阶段曾把「深色顶栏 `#1B1E33` vs 浅色顶栏 `#4F46E5`」记为品牌断裂。复查 `theme_schemes.xml` 后确认：`app_bar_bg` 本来就是**每套 scheme 各配一个值**，深色配深色栏是正确设计，不是漏改。

| scheme | 浅色顶栏 | 深色顶栏 |
| --- | --- | --- |
| indigo | #4F46E5 | #1B1E33 |
| teal | #0F766E | #10231F |
| violet | #6D28D9 | #1D1533 |
| graphite | #334155 | #1C2026 |

真正需要修的是**深色下按钮文字**：`on_primary` 在深色态取页面底色（而不是白），否则 `#818CF8` 底 + 白字只有 1.50:1。这条已由 `derive()` 处理。

## 五、没做的，以及为什么

诚实清单 —— 以下四条**没有完成**，不要当成已完成：

| 项 | 状态 | 原因 |
| --- | --- | --- |
| `fw_size_*` 75 档 → ≤12 档 | **未做**（仅 75→74） | 它是**部件尺寸**命名空间（108dp 的框、120dp 的区），纯数学吸附会真的改变部件大小，属于"改布局"而不是"改节奏"，超出"底层逻辑不变"的边界。 |
| 裸 dp 566 处 → 16dp 网格 | **未做** | 集中在 `tab3.xml`(35+26)、`tab1_ce.xml`(19+14)、`activity_cj_detail.xml`(16)、`tab1_corner.xml`(16+15)、`tab1_edge.xml`(16+13)、`timer_layout.xml`(14+12)。这些是逐元素手写的 margin/padding，吸附会改变真实布局，需要逐页目视回归，本轮没有足够验证预算。 |
| 趋势页空状态层叠 | **未修** | 图表和空状态不在 XML 里，在 `assets/segment_trend.html` 的 CSS 里；且需要构造空数据才能复现验证。 |
| 其他页图标 6 种色相 | **保留** | 图标本来就已走 `?attr/app_lit_tint_*`，且深色有对应浅色变体（`475569 → #cbcdd0`）。这是作者有意的彩色图标风格，属于"沿用现有设计风格"，强行统一成单色是主观决策，留给你定。 |

另外两个**已知但未处理**的观感问题：

- **主色按钮文字 4.47:1**，略低于 AA 的 4.5。但按钮文字是 16sp 粗体，按 WCAG "大号文字" 标准 3:1 已通过。若要压到 4.5 以上，把 `app_colorPrimary` 锚点从 `#6366F1`（indigo-500）换成 `#4F46E5`（indigo-600）即可（≈6.4:1），顺带和顶栏统一。
- **「换一组」与「开始作答」并排仍不等高**：两者都用 `@dimen/main_action_height`，差异来自各自 drawable 的阴影，不是尺寸令牌的问题。

## 六、复现方式

```bash
cd D:/Program/dsh/rebuild
SKIP_LX_UPDATE=1 bash build_lx.sh        # 第 1.5 步会自动跑 opt20 / opt21
```

- `opt20_palette_gen.py` 和 `opt21_dimens_ladder.py` 都是**幂等**的：已是目标状态时输出「已是目标状态，无需改动（幂等）」，0 改动。
- 备份写在 `tmp/`，**不能写进 `src/res/values/`** —— aapt2 会把 `.bak-*` 当非法资源路径，直接 `Execution failed (exit code = 1)`。
- `build_lx.sh` 里加了 `export PYTHONIOENCODING=utf-8`：控制台是 GBK，opt 脚本打印 ✅ 会 `UnicodeEncodeError` 把第 1.5 步整条链打断。
- 验收口径：`python tools/ui_audit.py`（每套 overlay 的独立色数 / 裸 dp / 裸 hex / dimens 档位 / 关键对比度）。

### 本轮新增文件

| 文件 | 作用 |
| --- | --- |
| `ui_palette_spec.py` | 语义调色板规格（角色表、派生规则、覆盖表），无 IO |
| `opt20_palette_gen.py` | 按角色改写 8 套 overlay 取值 + 徽章文字色兜底，merge 语义 + 幂等 |
| `opt21_dimens_ladder.py` | 圆角/字号/间距吸附到阶梯，只改值不改名 |
| `tools/ui_audit.py` | 验收脚本 |
| `build_lx.sh` | 第 1.5 步末尾追加两个 opt 调用 + utf-8 环境变量 |

以上均已同步到仓库 `source/build/`。

## 七、下一步建议（按优先级）

1. **P0 · 裸 dp 收敛**：`tab3.xml` / `tab1_ce.xml` / `activity_cj_detail.xml` / `timer_layout.xml` 四个文件吃掉 566 处里的 130+ 处。建议先只处理 **margin/padding**，不碰 width/height，一页一回归。
2. **P0 · 趋势页空状态**：改 `assets/segment_trend.html` 的层叠上下文（`position` + `z-index`），空状态不该压在三张统计卡上。
3. **P1 · 主色锚点下探到 indigo-600**：一次改 `app_colorPrimary` 锚点，按钮对比度 4.47 → ≈6.4，同时和顶栏统一。
4. **P1 · `fw_size_*` 按用途分三组**（图标 / 控件 / 区域）分别吸附，而不是全域数学吸附。
5. **P2 · 图标色相**：如果决定走单色图标体系，把 `app_lit_tint_*` 统一映射到 `text_secondary` 即可，零布局改动。
6. **P2 · 圆角语义化**：现在是 7 档数值，进一步可命名成 `radius_xs/sm/md/lg/xl/pill`，让「卡片 16 / 按钮 12 / 徽章 999」成为规则而不是巧合。
